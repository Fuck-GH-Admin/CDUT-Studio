# 材料审核 · 功能去混杂设计 R2

> 问题定义：**不是界面难看，是功能混在一起，用户不知道自己在干什么、下一步该去哪。**
> 依据：现有源码（`components/content-review/` 约 1.3 万行）逐组件清点 + `REVIEW-UI-REORGANIZATION-SPEC.md`。
> 本文只设计"哪个功能归哪个页面、每个页面只回答一个问题"，不讨论视觉细节。

---

## 1. 现状诊断：一处界面同时承担 6 件事

以右侧面板 `RightPanel.tsx`（现"待我处理"）为例，同一列里同时存在：

| 实际动作 | 本质是什么 |
|---|---|
| 开始审核、从头核对材料 | **发起运行** |
| 确认材料已核对、忽略材料、确认该项问题 | **材料/事实核对** |
| 修改认定、核验满足要求、结合最新材料 | **逐项认定** |
| 要求补件、登记已补交、前往添加证明材料 | **补件流程** |
| 通过、部分通过、退回补件、整案驳回、整案最终决定 | **阶段决定** |
| 审核建议（AI 生成） | **辅助信息** |

一个用户在"待我处理"里要同时分辨：我现在是在核对？在认定？在决定？还是在等补件？
其余面板同样混杂：

- `CenterPanel`：材料上传 + 申报事项 + 事实认定 + 证据关联 + 原文展示
- `V2CasePanel`：建案 + 案卷列表 + 材料 + 运行 + 报告 + 决定 + 申诉 + 离线包 + Agent 指派 + 时间线（整条生命周期塞在一个面板）
- `ContentReviewView`：全局导航 + 建案入口 + 三栏工作台 + 模板库 + 候选作者工具 + 批次 + 待办，全部并列为"同级分节"
- `BatchPanel`：批次列表 + 批次内进度 + 批量执行 + 集中处理 + 评分入口
- `TemplateWizardPanel`：模板库列表 + 模板编辑（字段/标准/材料/流程/输出）+ 示例包 + 导入配置 + 候选试跑入口

**结论**：不是缺功能，而是没有"一件事一个地方"。用户每点一个按钮都要重新判断当前语境。

---

## 2. 设计原则

1. **一页一问**：每个页面只回答一个问题；答案之外的东西不放首屏。
2. **对象先行**：先选对象（案卷 / 批次 / 模板），再进它的页；不允许在列表页出现某个对象的动作。
3. **动作唯一归属**：同一个业务动作只出现在一个页面；其它页面只能"跳过去"，不能重复提供按钮。
4. **列表只做检索**：列表页只负责找到并打开，不做任何修改。
5. **下一步唯一**：任何时刻只给一个"下一步"，且带具体目标（哪个案卷、哪一页、哪一条）。
6. **能力诚实**：没有的服务不画按钮；读取失败不显示为 0。

## 3. 用户任务模型（决定导航的最大单位）

| 用户想干的事 | 对应入口 | 一次会话内的典型路径 |
|---|---|---|
| 审一份案卷 | 案卷 → 打开 → 五页 | 材料 → 检查 → 办理 → 报告 |
| 处理今天要做的事 | 待办 → 点任务 | 直达具体案卷的某条对象 |
| 批量过一批申请 | 审核批次 → 批次详情 | 进度 → 集中处理 → 评分 → 定稿 |
| 写/改审核规则 | 审核模板 → 模板详情 | 适用范围 → 要求 → 标准 → 流程 → 试跑发布 |

四件事彼此独立，因此**全局导航只保留这四个对象入口 + 首页**。

## 4. 页面职责表（做什么 / 不做什么）

### 4.1 审核首页（`/home`）
- **只做**：回答"上次审到哪、现在该干什么"。当前案卷摘要、一条下一步、四项进度、最多 3 条本案待办、最近 5 份案卷。
- **不做**：不在首页编辑材料、不做认定、不做决定、不展示完整待办列表、不进入模板作者工具。
- **出口**：新建审核 / 继续审核（带目标页）/ 切换案卷 / 查看全部案卷。

### 4.2 案卷列表（`/cases`）
- **只做**：检索（标题/阶段/模板）、打开、新建。
- **不做**：不显示任何一个案卷的动作按钮（提交、检查、决定、导出都不在这里）。

### 4.3 新建案卷（`/case-new`）
- **只做**：三个起点（拖文件 / 选模板 / 空白）+ 模板要求填写 + 创建回执。
- **不做**：不在同一页展示已保存案卷列表。

### 4.4 案卷详情（`/case/:id`）—— 五页，各自一问

| 页 | 只回答 | 页面内允许 | 明确不允许 |
|---|---|---|---|
| **材料与事项** | 材料齐了吗？ | 材料槽选择、上传/登记、原件清单与解析状态、申报事项录入、材料覆盖提示 | 发起检查、认定、决定、导出、申诉 |
| **审核检查** | 哪条有问题？证据是什么？ | 发起检查（规则/AI，两种结果分别展示）、运行状态、检查结果列表、逐条查看证据与原文、逐项确认/忽略、发起补件请求 | 阶段通过/驳回、报告导出、模板编辑 |
| **办理与决定** | 现在该做什么决定？ | 当前阶段任务、补件回复登记、申诉提交/复核/撤回、阶段决定（通过/部分通过/退回/驳回/终审） | 上传材料、重新跑检查、模板编辑 |
| **报告与交付** | 交什么？ | 生成/查看/导出报告（全部格式）、离线任务包签发与回件导入、交付历史 | 修改决定、认定、材料 |
| **操作记录** | 谁在什么时候做了什么？ | 时间线、回执、运行历史、Agent 指派与授权状态 | 任何业务写入动作（只读 + 受控授权开关） |

### 4.5 待办（`/tasks`）
- **只做**：跨案卷任务列表，按"可行动 / 等待中 / 已处理"分组；每条带案卷名、阶段、处理身份。
- **不做**：不显示材料、检查详情；不提供批量决定。
- **出口**：点任务 → 直达对应案卷的对应页与对象。
- **兜底**：某案卷读取失败 → 单列"读取失败"，不并入零。

### 4.6 审核批次（`/batches`、`/batch/:id`）
- 列表：只做建批次、导入分案、检索。
- 详情四页：`案卷与进度`（只读进度）/ `集中处理`（批量执行与重试）/ `评委评分`（评分任务）/ `汇总与定稿`（排名与定稿）。
- **不做**：批次里不出现单案的材料表单与阶段决定；需要时跳单案。

### 4.7 审核模板（`/templates`、`/template/:id`）
- 列表：模板库（按业务分类、状态、发布版本）+ 新建/导入。
- 详情五页：`适用范围` / `信息与材料要求` / `审核标准` / `流程与输出` / `试跑与发布`。
- 候选作者（B1 第 51 套）与自然语言起草**只在"审核标准"与"试跑"里出现**，不再占据本案页面。

## 6. 导航与切换规则

```text
审核首页 │ 案卷 │ 待办 │ 审核批次 │ 审核模板
```

- 进入模块默认「审核首页」，不自动打开任何案卷。
- 全局导航高亮跟随对象：在案卷详情里高亮「案卷」，批次详情高亮「审核批次」，模板详情高亮「审核模板」。
- 对象详情内显示面包屑：`审核首页 / 案卷 / 名称`，可一键返回。
- 从待办/首页进入案卷时，**必须带目标页与对象**（如"检查项 #12"），不能只落到材料首页。
- 页面之间禁止隐式写业务：切页只切视图，不触发命令。

## 7. 每页信息预算（首屏最多放这些）

| 页面 | 首屏允许 | 其余折叠 |
|---|---|---|
| 首页 | 当前案卷摘要 + 1 个下一步 + 4 项进度 + 3 条待办 + 5 份最近 | 更多案卷 |
| 材料与事项 | 材料槽 + 材料清单 + 上传区 + 事项列表 | 解析详情、原始文本 |
| 审核检查 | 发起区 + 结果统计 + 问题列表（≤20，可筛） | 单条证据详情 |
| 办理与决定 | 当前阶段 + 可执行决定 + 待处理补件/申诉数 | 历史决定、逐条补件 |
| 报告与交付 | 报告入口 + 最近一份 + 导出格式 | 历史版本、离线包记录 |
| 操作记录 | 最近 20 条时间线 | 完整历史、回执原文 |

## 8. 与现有规范的差异（需要确认）

1. 规范 4.0 首页保留"切换案卷"；本文同意，但要求切换后**停在首页摘要**，不自动跳材料页。
2. 规范把"逐项认定"放在检查页；本文同样归到检查页，但要求**认定与补件发起分离**：认定是判定，补件是业务请求。
3. 规范把"补件详情"放在办理页；本文保留，并明确"要求补件"的**发起**按钮在检查页，两处不重复。
4. 规范未明确"AI 审核建议"归属；本文归到检查页结果区，且标记为辅助信息，不参与决定按钮。

## 9. 实施顺序（每一步都可独立验收）

1. **壳与导航**：五入口 + 对象详情壳 + 面包屑；页内先显示"迁移中"，不搬业务。
2. **材料与事项页**：只搬材料与事项；其余页保持旧实现兜底。
3. **审核检查页**：搬运行、结果、逐项核对与认定；补件发起在这里。
4. **办理与决定页**：搬阶段任务、补件回复、申诉、决定。
5. **报告与交付 / 操作记录**：搬导出、离线包、时间线、指派。
6. **模板与批次**：拆列表/详情与各自的分页。
7. **清理**：删旧容器、旧导航标识、重复按钮；逐条跑验收场景。

## 10. 验收（最小集合）

| 编号 | 场景 | 通过标准 |
|---|---|---|
| IA-A | 新用户进入模块 | 看到首页与"新建审核"；不需要先理解分节 |
| IA-B | 拖入材料建案 | 只创建一个案卷，落到材料页，失败文件可见可重试 |
| IA-C | 审一份有模板的案卷 | 材料 → 检查 → 办理 → 报告 四步各有唯一入口，无重复按钮 |
| IA-D | 同一案卷出现"有问题" | 从检查页某条问题可直接发起补件；办理页能看到该补件并回复 |
| IA-E | 拒绝通过 | 检查页不能直接通过；必须到办理页做决定，且理由必填 |
| IA-F | 待办跳转 | 点任务直达该案卷的对应页与对象，不再二次选案 |
| IA-G | 模板作者 | 不进任何真实案卷即可完成模板编辑与试跑 |
| IA-H | 批次 | 四个分页始终属于同一批次与轮次 |
| IA-I | 读取失败 | 任一处读取失败都显示具体原因与重试，不显示为 0 或空 |

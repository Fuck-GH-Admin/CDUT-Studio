# 27｜审核后台会话与模块设置修改建议

> 2026-10-11；代码核对基线 `29fc141afa9620f93e05e96953aa6e7ea269370a`，Electron `0.15.153`。**本文是待讨论方案，本轮只提交文档，没有实现隐藏会话。** 当前阶段成果及未完成项见 [28 号交付状态](28-review-stage-delivery-status.md)。

## 1. 建议与复杂度

建议将直接审核创建的 Pi 会话改为**归审核模块管理的持久后台会话**。会话可以创建、执行、续审和恢复；普通侧边栏、聊天搜索、最近会话和普通聊天标签页不显示它。用户通过案卷查看进度、结果、证据、错误和需要处理的请求。

持久会话仍有价值：续审需要上下文，运行恢复需要会话与 turn 绑定，停止和权限请求需要明确的执行对象。隐藏属于界面和归属策略，不应删除运行记录或业务审计。

完整改造属于**中等复杂度**，涉及共享类型、主进程、IPC、状态投影和审核页面。最费工的是人工交互转接、重启恢复以及历史会话迁移。仅在侧边栏加过滤条件工作量较小，但无法满足本需求：当前代码还会主动打开聊天、从事件重新加入列表，并通过通知跳转到聊天。

本轮不估算工期或完成百分比；应先确定交互承载页面和会话契约，再按下述阶段拆任务。

## 2. 当前代码实际怎样运行

### 2.1 直接案卷审核会创建普通会话

[`use-review-actions.ts`](../../../apps/electron/src/renderer/components/content-review/use-review-actions.ts) 的 `startPiReview`：

1. 从审核专属设置读取模型，未指定时读取全局 Agent 模型选择；工作区来自当前 Agent 工作区。
2. 根据案卷找可复用的 Pi 会话；从头审核、模型改变、归档或正在运行等情况会另建会话。
3. 调用通用 `createAgentSession`，使用 `review-operator` 预设，标题以“审核：”开头。
4. 把会话直接加入 `agentSessionsAtom`，再通过 `openSession('agent', ...)` 打开聊天标签。
5. 用真实 `sessionId + turnId` 准备案卷任务、附加案卷目录、发送消息，轮询持久化运行结果。

因此它目前是显式的普通 Agent 会话，并没有“内部审核会话”元数据。

### 2.2 批量/审核图还有另一条路径

[`pi-review-agent-client.ts`](../../../apps/electron/src/main/lib/review/pi-review-agent-client.ts) 为审核图的语义调用创建临时 Pi transcript，完成后删除，不通过通用建会话入口登记聊天列表。这条路径与上述直接案卷会话不同。

隐藏方案主要针对直接案卷 Pi 会话，并统一模块事件与设置策略；不把批量路径误判为都会创建侧栏会话。也不直接用临时 transcript 替换持久会话，以免丢失续审、人工交互和恢复能力。两条路径仍复用项目 Pi 内核。

## 3. 建议的会话契约

可在 `AgentSessionMeta` 中增加用途、可见性和所属案卷的信息，例如 `purpose: 'review'`、`visibility: 'internal'`、`ownerCaseId`。字段名及是否合并为一个判别联合需在实现时确定；普通旧会话缺省继续按普通可见会话处理。

主进程的审核专用“创建或复用会话”入口应根据已验证的案卷设置这些字段，返回案卷任务状态和必要的运行标识。不要让通用渲染接口任意指定所属案卷，避免错误绑定。隐藏标识只影响展示，不授予额外工具或业务写入权限。

模块必须持久保存 `caseId → sessionId → runId/turnId` 的关系，并沿用现有审核 assignment、输入版本、证据、停止与撤销校验。已有 `getPiReviewSessionV2` 和运行账本可作为基础，具体索引与清理关系需要统一。

不要借用 `draft`：草稿发送首条消息后会晋升；也不要用 `archived`：归档会影响会话复用且仍可能出现在归档搜索。标题前缀和 `review-operator` 预设都不足以单独证明案卷归属。

以下均为建议落点，当前实现尚未修改。

| 范围与代码 | 建议改动 | 需要保留的行为 |

当前 `LIST_SESSIONS` IPC 还会为列表内会话启动附加目录监听。不可直接全局过滤 `listAgentSessions`：内部清理、工作区删除、迁移和恢复也使用它。应提供明确的 UI 查询范围，把必要的监听初始化移到运行/恢复路径。

通用 `CREATE_SESSION` 当前会尝试调用 `feishuBridgeManager.ensureSessionMirror(session)`。内部审核会话默认关闭该聊天镜像副作用；通知策略和镜像策略需分别定义。

## 5. 设置放在哪儿

审核已有 [`ReviewSettingsPanel.tsx`](../../../apps/electron/src/renderer/components/content-review/ReviewSettingsPanel.tsx) 和 [`module-settings-store.ts`](../../../apps/electron/src/main/lib/review/module-settings-store.ts)，配置文件 `review-module-settings.json` 当前保存 `agentModelSelection`。可以在这里扩展，无需复制整套聊天设置。

| 设置/信息 | 建议位置 | 处理方式 |
| --- | --- | --- |
| 模型、渠道 | 审核专属设置，现已有入口 | 保存全局渠道/模型 ID；API Key 继续由全局渠道管理。无效选择明确报错 |
| 推理强度 | 审核设置的高级项 | 使用已有 Pi 支持的档位；默认跟随受控预设/全局设置，不显示模型不支持的选项 |
| 本次实际模型、推理档位、模板版本 | 案卷运行详情 | 启动时保存有效设置快照；运行中改设置只影响后续运行，续审是否换会话明确提示 |
| 进度、停止、重试、从头审核 | 案卷任务区 | 使用真实 run/session；切换页面继续运行，重启后的中断不能伪装成完成 |
| 工具权限确认、提问、计划确认 | 审核前台的待处理任务区/弹窗 | 展示具体请求及案卷，支持同意/拒绝/回答；保留现有权限校验 |
| 完成、失败、待处理通知 | 审核专属设置 | 点击进入案卷；待处理请求不能因通知关闭而永远不可见 |
| 工作区和案卷目录 | 主进程案卷执行策略 | 从案卷确定，不再无意继承当前聊天工作区；不提供任意宿主目录作为默认工作空间 |
| 预设、可用工具、权限边界 | 主进程审核执行策略 | 复用项目权限体系；可展示策略说明，不以隐藏会话为由自动放行工具 |
| 上下文窗口/最大输出 | 全局模型配置 | 审核使用已配置的模型能力，不新增第二份可能冲突的配置 |
| 模板、依据、材料、批次自动处理授权 | 既有案卷/模板/批次页面 | 业务数据和逐批授权继续留在原位置；会话可见性不改变自动通过门槛 |
| 超时、重试、并发上限、运行日志保留 | 先由模块执行策略确定，必要时开放高级设置 | 与队列策略统一；自动重试不得重复写入业务决定 |

当前直接审核的模型回退来自 renderer Agent atoms，审核图的模型网关读取全局配置。后台化时需在主进程统一“跟随全局”的含义，避免两个入口选择不同模型。建议明确为全局默认配置，并在运行前显示最终有效选择；不要依赖用户刚打开的聊天。

现有 `AssistantDrawer` 是独立的案卷助手线程，不是普通 Agent transcript 的后台容器。可复用其交互样式，但权限请求、执行状态和运行日志仍需专门接线。

## 6. 生命周期与迁移

1. 同案续审复用可用会话；换模型、从头审核和忙碌会话的处理沿用现有规则。不同案卷不能复用同一上下文。
2. 离开页面后由主进程拥有运行任务。停止必须中止真实 Pi 执行、结束或撤销对应 assignment，并保存明确终态；不能只停止前端轮询。
3. 重启时从持久绑定恢复任务状态；无法恢复的执行明确记录中断，提供定向重试。会话文件存在不代表上一轮仍在运行。
4. 历史会话只依据可信案卷 assignment/运行绑定迁移；先校验唯一归属，歧义时保留现状。不得仅凭“审核：”标题或预设批量隐藏用户聊天。
5. 迁移同时处理已保存聊天标签、最近选择和通知目标；需幂等、可记录并能撤回展示标记，不删除原 transcript。
6. 会话清理与案卷审计分开：结果、证据、决定和版本是业务记录；调试 transcript 可按独立保留策略处理。删除案卷、删除工作区及手动清理时明确关联规则。
7. 模块产生的子会话/分叉应继承内部展示策略及所属案卷；主动导出可读日志使用案卷动作，不把它自动晋升为普通聊天。

## 7. 建议实施顺序与验收

**第一阶段：归属与查询。** 增加持久内部会话元数据、主进程审核创建入口、查询范围和可信迁移；全局维护查询仍覆盖全部会话。

**第二阶段：运行与交互。** 去掉普通聊天导航，提供案卷进度、停止、错误和权限/提问处理；转接通知、视觉预览和桥接策略，统一模型回退及设置快照。

**第三阶段：恢复与回归。** 验证重启、切页、同案续审、跨案隔离、历史标签和归档/搜索；通过行为验收后再默认启用。

建议后续实现采用以下 BDD 场景；**这些是待编写的验收条件，本轮没有新增或运行这些测试**：

- 给定已配置模型，启动案卷审核，侧栏/置顶/归档/搜索/最近聊天都不出现内部会话，案卷显示真实进度。
- 给定正在后台运行的案卷，切换到普通聊天/设置，再收到会话投影事件，内部会话不被重新加入聊天列表。
- 给定权限或提问请求，案卷显示待处理；用户拒绝能结束相应等待；无回答不被自动同意，通知点击返回正确案卷。
- 给定视觉预览请求，案卷能够完成预览确认协议，证据回执仍绑定本次材料版本。
- 给定停止、超时或进程重启，持久状态准确，旧 assignment 不继续写结果，重试不重复处置。
- 给定两个案卷及同案续审，上下文与请求互不串案；模型变化和输入变化按现有有效性规则创建/复用会话。
- 给定运行中修改审核设置，当前运行快照不变，下一次运行使用新配置。
- 给定已有普通/审核/歧义会话与保存标签，迁移只隐藏可信归属会话，不丢记录，重复迁移结果一致。
- 给定启用飞书桥接，内部审核不会自动建立普通聊天镜像；运行目录监听、全部会话维护和清理仍有效。
- 给定批次自动处理未授权，后台化不能绕过全局代批、模板、批次或逐案证据门槛。

## 8. 本轮交付边界

本轮交付源码阅读结论和修改建议，推送到测试仓库；上游阶段 PR 同时提供本方案供评审。当前运行仍会创建并打开可见的普通审核会话。后台化、审核设置扩展和交互转接需另一次实现及验收。
